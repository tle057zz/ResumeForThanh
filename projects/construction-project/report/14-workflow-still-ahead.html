Section 4Summarise each question

One notebook, after the registration. It reads the question from gold.rfi_analytics and writes a one- or two-sentence summary back beside that row in Databricks, in a field named rfi_short_summary. The summary is for the register preview and for the copilot. The full question stays in the table.

The summary uses only the words in that RFI. It keeps the technical point, says when the note is unclear, and leaves out cost, schedule, and any fact the row does not contain. A check on RFI-002 should come back close to this: the contractor asks which battery energy storage capacity governs, because the solicitation and the drawings disagree.

When the export is back, this section will show how many of the 107 summaries were written, two or three examples, and any row the model left blank.

Section 5Search by meaning

One notebook. It embeds each question with databricks-gte-large-en, the same 1024-number vector used by the classifiers, and once the summaries exist it embeds those too. A search phrase is embedded the same way. The notebook ranks the 107 RFIs by closeness and returns the nearest ids. The ranking stays in the notebook. This workspace is not set up for a managed vector index.

Section 6RFI copilot

One notebook, after the summary and the search exist. A question in ordinary language is answered from the 107 RFIs by calling a fixed set of tools:

ToolWhat it is allowed to do
SQL countsRead gold.rfi_analytics for a count, a rate, or a list of ids
Meaning searchReturn the nearest RFIs from the notebook ranking
SummaryReturn rfi_short_summary for the ids already retrieved
ClassifiersCall the three champion models on an embedding, for discipline, issue type, and document impact

The first questions to run are ones the tables already answer: how many Electrical RFIs there are (40), which RFIs are still open (the eight tasked to CT), and which RFIs change both a drawing and a specification (the 16 Both rows). A question about project profit, or about any fact outside these 107 rows, is answered as out of scope. The reply names the ids or the count it used.

When the export is back, this section will show each question, the tool that ran, and the answer checked against the gold table.

Section 7Check the answers

After the copilot notebook has a few answers, a short check list is scored by hand against the gold table. Each line has the question, the expected count or the expected RFI ids, and whether the question can be answered from this register. The scores to keep are: the count matches, the ids match, the wording stays inside the row, and an out-of-scope question is refused.

The same note records the model versions in use, that a person reviews the answer before it is treated as project direction, and that the classifiers and the summary support the team. They do not close an RFI or change a drawing.

Section 8How this page will change

The order stays as it is: registration, summary, search, copilot, then the check list. A finished step keeps its heading and replaces the plan paragraph with the printed result. A step that has not been run stays written as the work still to do.
